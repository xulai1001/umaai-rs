# umaai_review · 单局复盘归因

> 计算下沉到 Rust（`umaai_review` bin），判断力留给本 skill。
> bin 产出 `brief.md`（六问事实预答，**主路径，一次 Read**）、`digest.json`（完整数据，
> 定向复核用）与 `report.html`（网页版）。
> **brief.md 齐备时不派子代理**——结果已全，子代理只服务于 brief 缺失的降级路径。
> 口径速查见 `reference/metrics_glossary.md`；拟人化口吻见 `reference/persona.md`
> （可选覆盖层，可删可改；缺失时按默认平实专业口吻输出，流程与检查项不受影响）。
> 降级路径（brief 缺失时）的探查提示词见 `reference/probe_prompts.md`（已固化，勿临场手写）。
> **马娘专属判据**（如某回合有强敌）见 `reference/uma_specific.md`，**由模型层判读**——
> Rust 只出通用事实，不做专属判定。

## 职责边界与工具偏好

**本 skill 只做三件事**，计算与判定不在此层重复（那在 `umaai_review` bin 里）：

1. **叙述化结论**——把 brief.md 的事实转成人话叙事（六问骨架见「归因框架」）
2. **渲染结果**——回填 report.html 的 4 处叙述占位、按需补数据块叙述（工作流程第 6 步）
3. **回答用户的问题**——针对具体回合 / 决策的追问，必要时回 brief / digest 定向取数

**工具偏好**：需要脚本时**优先 Python**（写临时 `.py` 一次加载多块，或简单场合 `python -c`）；
Python 不可用再考虑其他脚本（`node -e` / PowerShell / Bash）。两条已知理由：

- `python -c "...\"..."` 的嵌套引号会被 PowerShell 吞掉 → 复杂取数一律写成临时 `.py` 再跑
- 部分会话 PowerShell 执行成功但 stdout 为空（pitfalls 第 8 条），Python 无此现象

解析 digest.json 的取数片段（**Python 与 PowerShell 两版**，均已实测）见
`reference/probe_prompts.md`；跨语言坑位见 `reference/pitfalls.md`。

## 工作流程

1. **定位局包**（三级优先，逐级回退）：

   | 优先 | 来源 | 说明 |
   |---|---|---|
   | ① | **会话中拖入 / 上传的文件** | 直接用其路径 |
   | ② | 用户明确给的路径 | 任意位置，绝对或相对均可 |
   | ③ | `<umaai_root>/logs/` 下最新 `game*.zip` | 日志**每局轮换**（实测 game1429→game1430 被顶掉），**每次现取、不缓存文件名** |

2. **运行分析引擎**，产物落**当前工作区** `<cwd>/game{id}/`（不写沙箱外的临时目录，避免权限询问）：
   `brief.md`（六问事实预答，喂归因）+ `digest.json`（完整结构化指标，定向复核用）
   + `report.html`（只给路径不粘贴）：

   ```powershell
   <skill>\bin\umaai_review.exe --zip <局包> --out <cwd>\game{id} `
       --gamedata <gamedata 目录> [--narrative <叙述文件>]
   ```

   - **`--gamedata` 必须显式传**：局包可能在任意位置（拖入的文件常在临时目录），
     「从局包向上找 gamedata」不可靠，所以 gamedata 只按 **umaai 目录**解析：
     ```
     <umaai_root>/gamedata          ← umaai_root 读自本 skill 目录的 local_paths.json
       ↓ 没有 umaai_root / 该目录不存在
     <skill>/data/gamedata/         ← skill 自带，bin 会标「旧版数据」（context.criteria 出注记）
     ```
     **自带那份放在 `data/` 下**：bin 要求目录名必须是 `gamedata`（umasim 硬编码相对路径读文件），
     但位置任意——放 `data/` 这层就与用户自己放的 `<skill>/gamedata/` 分开，
     升级覆盖解压时不会互相动到。
     没有 `local_paths.json` 时**询问用户一次**「umaai 目录在哪」，确认后写入
     `local_paths.json`（`{"umaai_root": "..."}`），下次先读它。**不使用环境变量**（面向初级用户）。
   - `--out` 显式指向当前工作区；bin 默认落在局包同级，拖入的局包会让产物散落到临时目录。
   - `--narrative <md>`：第 6 步写好的叙述文件；**首次运行不必带**（此时 report.html 留占位），
     写完叙述后带它再跑一次即得到完整报告。
   - exe 不可用降级：`Expand-Archive` 解包，直接读 `decisions.csv` + `meta.json` 做决策链路 / 运气分 / 置信度分析（丢失依赖快照时序的检查项），结论需注明降级。**此路径下 brief.md 与 digest.json 都不可得**，第 3 步改走「解包数据 + 人工判读」，不适用下方的 brief / digest 分支。
   - **背景图先拷再跑**：想让报告带背景，必须**先建好 `--out` 目录并把 `reference/yayoi.png` 拷进去**，再跑 bin——
     模板按「输出目录里有没有该图」一次性决定背景（相对路径 `url("yayoi.png")`，只认与 report.html 同级的文件），
     跑完再拷就晚了（补图只能重跑 bin）。缺图不影响流程，只是没有背景与半透明卡片。详见 pitfalls 第 28 条。
3. **读 brief.md**（六问事实已由 bin 预答，**一次 Read** 即可动笔）：

   > **brief.md 齐备时，不派任何子代理。** 六问与 overview 所需数字已全部预答在 brief 内，
   > 主代理读完直接写叙事即可——再派子代理只是重复取数、白增往返。
   > 子代理**只服务于下方「降级」分支**（brief 缺失时）。

   - 路径 `logs/game{id}/brief.md`（约 11KB，为 digest.json 的 1/18），章节：
     §0 口径 / §1 总体（含 §1.1 五维显示值逐年 + 上限 + 触顶维、§1.2 训练画像、数据健康度）/
     §2 运气走势分段 / §3 极值回合（含 flagged 与当回合决策）/
     §4 继承质量 / §5 其他波动来源（体力低点、干劲掉落与恢复、分身彩圈、赛程）/
     §6 建议执行（偏离行含**存疑**自动标注）/ §7 检查项。
     六问与 overview 所需的数字（含五维显示值）已全部在 brief 内，**常规复盘无需再读 digest**。
   - brief 只给**事实与预格式化表格**，不下叙事结论——叙事仍由本 skill 写。
   - 仅在确实需要 brief 未覆盖的细节（如某回合完整候选表）时，**主代理自己**回 digest.json
     定向复核该块（分块提取、不整读；字段坑位见 [reference/pitfalls.md](reference/pitfalls.md)）——
     这仍是主代理直接取数，**不是**派子代理。
   - **降级（只有这个分支才考虑子代理）**：brief.md 缺失（旧版 exe / exe 不可用）时，按
     [reference/probe_prompts.md](reference/probe_prompts.md) 分组探查 digest.json——
     子代理可用则**同一条消息一次发出**并行派发（一组一代理），不可用则由主代理按同序**串行执行**。
     探查前必读 pitfalls；digest.json 是单行紧凑 JSON（200KB 级），任何代理都**不要整读整贴**。
     各组结论互相矛盾或明显缺数据时，定向复核该块（仍分块提取，不整读）。

4. **归因**：见下节框架与口径。**先查 [reference/uma_specific.md](reference/uma_specific.md) 有无本局马娘的条目**，
   有则按条目口径判读（该文件还列了「运气分下降」的几种通用成因，判读前先排除）。
5. **输出**：见输出纪律，叙事结论只在对话输出不落盘。
6. **写叙述文件 → 注入 report.html**（**不手工回填 HTML**）：

   ```powershell
   # ① 写叙述文件（4 段，`<!-- key -->` 标记分隔；顺序不限、可只给部分）
   #    路径 logs/game{id}/narrative.md
   # ② 一条命令注入（Rust 把 4 段拼进 report.html）
   target\release\umaai_review.exe --zip logs/game{id}.zip --narrative logs/game{id}/narrative.md
   ```

   > **为什么不手工回填**：report.html 全文约 27KB（含 3 个内联 SVG），手工 Write 既费 token
   > 又有抄坏图表的风险；脚本替换则要处理锚点与转义。现在 skill **只写 ~1.5KB 叙述**，
   > HTML 全文由 Rust 生成、叙述经 `|safe` 原样注入。
   > **narrative.md 是输入文件、会保留**：重跑带 `--narrative` 即可复原（不再像手工回填那样被抹掉）。

   | 标记 | 内容 | 位置（单一两栏网格） |
   |---|---|---|
   | `<!-- overview -->` | 总体描述（Q1 + 增长顺序） | 「总体 / 总结」合并卡上半（头部双卡行右卡；左卡 = 终局估分 + 图1 五维） |
   | `<!-- luck_trend -->` | 运气走势分段解释（Q2，**与图3 关注点编号对应**——编号解释只在这里，图内不注记） | 「运气走势 / 检查项」合并卡上半（图4 心情走势之后） |
   | `<!-- findings -->` | 检查项 / 偏离 / 继承 / 彩圈的重要事实（Q5/Q6 摘要） | 「运气走势 / 检查项」合并卡下半 |
   | `<!-- summary -->` | 总结与下一局建议 | 并入「总体 / 总结」卡下半 |

   > 报告四图：图1 五维属性在头部「终局估分」卡内，图2 训练分布 / 图3 运气走势 /
   > 图4 心情走势为独立图区。图4 的干劲阶梯线与**掉干劲区间注记由 bin 自动生成**
   > （「t12..t14（5→4，t15 恢复）」式），叙述层无需为它写内容；对话叙事的干劲
   > 纪律不变（只讲异常，见输出纪律）。

   - 每段内容 = 复盘叙事对应段，**数据与 brief.md 一致**；写 HTML 标签，不做转义
   - **篇幅纪律（2026-10-08 拍板）**：每段 `<ul><li>` 分条、**4-6 条、合计约 150-200 字**，
     只列最重要的内容——报告是两栏紧凑版，长篇叙述放对话输出，不放报告
   - 段内容为纯 HTML 片段（裸 `<ul>` 即可，模板占位处直接注入，不必包 `<section>`）
   - 不给 `--narrative` 时 report.html 保留 `NARRATIVE:` 占位（旧流程仍可用）

   骨架（模板已给 ul/li 样式，直接用）：

   ```html
   <ul>
     <li>终局 <b>71007（US6）</b>，AI 端估算口径……</li>
     <li>增长顺序先耐后速：……</li>
   </ul>
   ```

   写叙述时注意：
   - **重要数字加粗**：评分 / 等级 / 终局运气分 / 极值 Δ / 继承贡献与偏差等关键数字
     用 `<b>` 包裹；一段内粗体三五处以内，不再展开表格
   - **overview 要点（2026-10-08 拍板）**：首条固定措辞「终局AI侧估分（略高于实际
     分数）X（等级）；运气分 Y（判语）」；增长顺序（先 X 后 Y，结合卡组）/ 涨运气
     的训练类型 / 一致率各一条（数字取 brief §1 与 §1.2）；**五维数值不列**
     （图1 五维属性已详示）
   - **luck_trend 与图3 关注点对应（2026-10-08 拍板）**：图3 只在图上标编号圆圈，
      **编号解释只写在走势文字里**（图内不注记）。编号推导＝brief §3 取 top_gain
      前 3 + top_loss 前 3、按回合去重后**按回合升序**编号 ①-⑥；走势每条写
      「① t24 -11268（性质）」式锚点，口语化表述（「账面跳变」「回血」「阴跌」），
      判据细节归 brief §0；图上底色＝正 / 负运气区（浅绿 / 浅红），「阴跌段 /
      转正段」的描述与底色对应
   - **findings 只讲重要事实**：命中检查项、偏离（含对应候选次选）、继承判断、
     彩圈吃到情况各一条；正常项不提；**不再写偏离表格**（报告表格区已删，偏离明细看 brief §6）
   - **干劲只讲异常**：brief §5.2 写「无未及时处理的掉干劲」时就完全不提干劲
   - **继承与分身不再有报告叙述位**：两者在报告中是两栏表格区（分身彩圈 / 继承质量），
     关键判断（偏优 / 偏弱、吃到与否）并入 findings 段的一两句话
   - **叙述口吻与对话一致**：persona 启用时按人设书写（summary 尾可署「理事长 秋川弥生」），
     网页版与对话版只是同一复盘的两个出口
   - **背景图（可选装饰）**：把 `reference/yayoi.png` 复制到输出目录（bin 的 `--out` 目录，即 `<cwd>/game{id}/`）即可——
     **背景 CSS 由模板自动加**（bin 检测到该文件才启用背景与半透明卡片），不必改 HTML。
     图片缺省时跳过，报告照常。**顺序要求**：图片要在跑 bin **之前**放好，否则那次渲染不带背景（pitfalls 第 28 条）

## 归因框架

bin 已自动产 findings，**读 brief §7 检查项**（已按 warn 优先排序）+ 对应章节复核即可。后续增补检查项按「判据 / 取数 / 输出 / 状态」四要素格式追加，不动框架。

| 检查项 | 判据 | 取数（brief 章节） | 状态 |
|---|---|---|---|
| 目标赛未跑赢 | 必赛回合不在 raceHistory（只记跑赢） | §7 + §5.4 赛程 | 已实现（已验证） |
| 关键资源过早耗尽 | 友人次数达上限距结束仍远 + 此后体力低点 | §7 + §5.1 体力低点 | 已实现（已验证） |
| 心情掉落后未及时恢复 | 干劲下降后 3 回合无出行/休息且未回升 | §7 + §5.2 干劲 | 已实现（已验证） |
| 训练失败候选 | AI 建议训练 + 五维零增长 + 体力有消耗 | §7（info 级） | 候选清单，人工复核事件影响 |
| 超级拉面期盈亏 | turn≥72 回合合计Δ 正负（超级拉面分身分身机制保证落位，没吃到不算亏） | §7 + §2 超拉期净变 | 已实现（已验证） |
| 执行偏离 | ai_choice ≠ actual_action | §7 + §6 偏离表 | AIRedirector 局仅作校验、不产生结论 |

**归因口径（用户拍板）**：

- 目标赛未跑赢、超拉期连亏、掉干劲本身都是**运气不是操作**——输赛随机、掉干劲是数据外事件带来的（输赛不掉干劲，快照无事件明细列待查）、超拉期估值走低是落地差。唯一例外「掉干劲后未主动恢复」原是已知偏差②（模拟高估事件回复）导致的决策倾向，该偏差 2026-10-01 已修复、新录制缓解，仍作观察项与改进方向。
- 运气极值：**brief §3 每个极值回合已带位置标记**（年界 / 继承 / RMJ / 开局地区选择）——跨年假跳 2026-10 修复后已基本消除，标记位置如今的跳变大多是**真实结算 / 继承落地 / 选择本身**的变化，按性质归因、不当连续损益读；只有再出现一增一减的配对式大幅账面波动才降级。`turn_delta` 是期望终局分变化，不等于属性增量，同回合多段以合计观察。**正跳另查切者**：`timeline.is_qiezhe` 由 false→true 的回合是获得切者（能人），T(n) 有 PT 项 ×1.1 量级的期望跳升，属真实好运，叙事可点出。
- **学技能标记**：**技能点只减不增——减少就一定是玩家学了技能**，这类回合带 `skill_learned(-Npt)` 标记。花掉技能点后 AI 的期望终局分把「未花掉的技能点」计入价值 → 运气分下降，**不是真实运气下降**，归因时降级、别读成倒霉。常见于马娘专属判据（见 `reference/uma_specific.md`）。
- **自选比赛期限波动（>8000 的运气波动通常属此类）**：窗口截止前未达标时 MCTS 对「将育成失败」大幅低估 → 骤降，补赛达标后回升，**净变≈0、不影响最终运气**。这类回合带 `free_race_deadline_swing` 标记，`schedule.notes`（brief §5.4）有一行完整注记——叙事要点出「**自选比赛极限达标**」这个操作，**不能读成坏运气**。**注意年界标记会同时命中且归因有误**（game3099 t22/t23 标 `year_boundary(24)`，真实原因是自选期限），以 `free_race_deadline_swing` 为准。
- **旧局包假跳（brief §0 录制年代注记自动标注）**：2026-10-03 前录制的局 turn 2 有 +1300 量级假跳（链式推进漏加 NPC，已修复）；2026-10-07 前录制的局 turn 71→72 有 −1000 量级假跳（URA 赛后加成丢失，已修复）。brief §0 标了的回合按程序性波动降级。
- 运气阴跌口径：display 运气分含 `mcts_turn_bonus`（MCTS 预期的每回合平均运气增长），实际游戏非线性——第 1 年增长慢于预期、或第 2-3 年持续没有好训练，都会呈现为持续小亏的阴跌。一句话总口径：**运气增长慢于预期，不进则退**，叠加残余估值偏差（RMJ 按每年成功假设等，见 brief §0）。不写成「小额落地差」这类含糊归因，也不读成「每一回合都在倒霉」。
- 执行偏离是估算：actual_action 由状态差推断，判据为「**先判训练、再解释体力**」——目标维**推荐维优先**（它是最大增量，或自身增量 ≥ +20），否则取最大增量；体力只作否证（体力 ≥ +25 且目标维 < +20 → 休息）。**偏离主要是选了 2-3 选**：brief §6 偏离表的「对应候选」列给出实际动作命中的候选编号（如 #2 力训练），有编号的是**换了个候选**、不必然是不听建议，叙事按「选了次选」表述；「—」才是候选外操作。**brief §6 已按此口径自动标「存疑」**（建议维已触顶 / 推断维与建议维相邻 / 体力卡休息判定线），标了的照抄存疑、不硬下结论。
- **训练画像（brief §1.2）**：逐年「训练次数 × 五维净增 × 运气归属」——**增长先后顺序**从这里读（如第 2 年带 1 张卡的耐增长反超带 2 张卡的速＝先耐后速），结合卡组构成点名「卡少却反超」的维与时机；「涨运气的训练主要类型」读运气归属行（回合合计 Δ 按当回合训练维归属）。净增含事件 / 继承 / 比赛，读顺序而非纯训练收益。
- 继承偏差为负 → 质量偏弱，是确实的损失，如实报数不打折（brief §4 已给「偏优 / 正常 / 偏弱」判断列）。
- 分身：`rainbow_luck` 归好运、`rainbow_strategy` 归好策略；价值是提高训练效果（玩家已知，叙事不解释）；**地区分身彩圈吃到与否直接读 brief §5.3 的「吃到=是/否」**（当回合训练命中彩圈位 = 吃到）；**地区分身一张彩圈都不落 = 明显的坏局面，须明确写出**（一般都会产生一些），定性为坏运气、且落位随机无可操作空间；**超级拉面期的分身彩圈不做文字分析**（数据只在表格，不进叙事）。判据全文见 [reference/metrics_glossary.md](reference/metrics_glossary.md) 的「地区分身彩圈为 0」节。
- **地区选择与属性无关**：`region_select` 带来的期望跳变是固定运气波动（与 `region_select(y1)` 同类，程序性），**不得写成「拿来补某维属性」的操作建议**。判据全文见 `reference/metrics_glossary.md` 的「地区选择」节。
- **属性低 ≠ 建议练该维**：不得仅因某维终局偏低就建议玩家加强该维训练——「能训练的属性」依赖玩家携带的卡组，卡组未携带的维（如力/根）偏低是**客观事实**，不是操作问题；要补维只从三条路里给建议：加强对应主属性的训练（练速可以补力、练耐可以补根、练根可以补速/力）、选用副属性更强的支援卡（如拉根能力更强的耐卡）、改进种马质量争取继承更多对应属性。判据全文见 `reference/metrics_glossary.md` 的「五维偏低与补维建议」节。
- 五维叙事报**显示值**：**brief §1.1 五维表已是显示值**（真实值 > 1200 部分减半，bin 已换算）；同表的「上限」与「触顶维」用真实值判定，两者不要混读；评分与运气分不受此换算影响。
- total_luck_end `< -2000` 才判「这局运气差」（brief §1 已给出定性）；旧局包（2026-10-01 前录制、无 keyEvents）曲线系统性略偏低——brief §0 的录制年代注记会自动标注，标了的按偏低读。
- 判据待实测项谨慎下结论：训练与体力健康、吃面节奏、友人完成度、free_race 次数与时机、状态健康、属性溢出。

## 输出纪律

- **口吻**：马娘玩家术语优先——彩圈 / 友情训练 / 羁绊 / 干劲 / 体力 / 吃面 / 超级拉面 / 目标赛 / URA 决赛 / 继承 / 出行 / 友人卡；少用内部字段名（`turn_delta` 说成「运气波动」，`flagged_turns` 说成「程序性波动回合」）。
- **少括号少破折号**：口径与回合号融进句子（例：「终局 62500，评价 UA9。终局AI侧估分，比实际分数略高一点」），不要堆插入语。
- **语气基调**：LG 档（final_score ≥ 76000）放开夸，夸到回合与数字；坏局减弱负面、给希望；根因是继承弱时一句带过。
- **篇幅**：原因一两句点透，不长篇大论；继承 / 分身 / 干劲 / 自选比赛 / 执行偏离用小表格或分条，正文只留一两句解释；额外的判据、口径说明、待定项统一放结尾一小节**分条列出**，不穿插在分析中间。
- 运气数字带符号表示（如-3526, +800）。
- **叙事纪律（用户拍板）**：
  - 全胜不提：比赛全赢是基本操作，输赛才展开
  - 安抚不出口：「不深究」「不数落」「不打折扣」「一笔带过」不落正文——说出口就成了数落，弱化体现在措辞与详略上
  - 玩家已知口径不解释（分身价值 = 提高训练效果），只报观测数据
  - 自选比赛两类分开：`free_races`（区间内剧本要求的自选，含 required 次数与实跑）与 notes 的「区间外自选」（不在任何要求内自发跑的）分别列行；马娘没有自由比赛区间数据时如实说明
  - 干劲恢复一般是做了动作才回升（出行 / 休息 / 事件选项），不表述成自然回升，恢复列写具体动作
  - turn 72 兜底：超级拉面期开始自动加体力与心情（干劲），不建议 72 前专门补状态
- **persona**：启用时 `execution.ai_choice` 统一改称理事长自己的建议（第一人称「我当时的建议」），叙事不出现「AI」字样；无论有无 persona，数据与结论必须与 brief.md 一致，拟人化只改表达层。
- **结构** = 六问顺序 → 改进建议 → 末尾集中一小节口径备注（待定项、读数须知）→ `report.html` 路径收尾；叙事结论对话输出，叙述四块按工作流程第 6 步写进 `narrative.md` 并注入 report.html。
